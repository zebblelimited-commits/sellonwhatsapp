📋 Master TODO List: SellOnWhatsApp Roadmap
Here is the complete summary of our architecture and the steps needed to finish the platform.

Phase 1: Multi-Seller Checkout & Escrow Split (Next Immediate Step)
///////////////////////////////////////////////////

Build /api/checkout/create-orders Endpoint:

Accept the grouped cart payload (Buyer ID, Address, Seller Orders array).
Financial Split Logic: Calculate Product Cost (Escrow), Shipping Cost (Platform Ops), and Platform Fee (Platform Rev).

Tier Check: Query the stores collection to check if the seller is isPartner (Pro Max). If true, set seller commission to 0%. Otherwise, apply 1.5%.

Database Writes:
///////////////////////////////
Create a parent checkoutSessions document.

Loop through seller orders and create individual orders documents (Status: PAID_HELD).

Do not create shipments yet (that happens after courier selection/pickup).

Integrate Payment Gateway (Paystack/Flutterwave):
Pass the Grand Total to the gateway.
On webhook success, update order statuses and trigger the next steps.

Phase 2: Courier Aggregation Layer (Shipping)
///////////////////////////
Database Setup:
Create couriers collection (Name, Logo, Base Rate, RatePerKg, Multipliers).
Create shipments collection (Linked to Order ID, Status, Tracking Number).

Shipping Calculation API (/api/shipping/calculate):
///////////////////////////////

Fetch active couriers from DB.
Apply pricing formula: (Base + Weight * Rate) * State Multiplier.
Append the "self_arranged" (0 cost) option to the response.

Post-Checkout Shipment Creation:
/////////////////////////
If Courier selected: Create shipment doc, deduct shipping fee from Platform Ops account to pay courier.
If Self-Arranged: Set order status to AWAITING_PICKUP, do not create shipment.

Shipment Lifecycle Tracking:
///////////////////////////////
Build logic to update shipment status (PENDING_PICKUP -> IN_TRANSIT -> DELIVERED).
Trigger Escrow Release when status hits DELIVERED (or buyer manually confirms).

Phase 3: Seller Subscriptions & Monetization
//////////////////////////////

Subscription Tiers Logic:

Update stores collection to track subscriptionPlan, subscriptionStatus, and subscriptionExpiry.
Implement the 1.5% Buyer Fee / 1.5% Seller Fee logic (with 0% override for Pro Max).
Add a flat ₦100-₦200 Logistics Handling Fee per shipment.


Auto-Renewal System:
////////////////////////
Set up Firebase Cloud Functions (Cron job) to check expiring subscriptions.
Charge saved payment method and extend subscriptionExpiry.
Implement 7-day grace period logic.


Phase 4: Boost Store Feature (Visibility)

Database Setup:
/////////////////////////
Create storeBoosts collection (Tier, Status, Start/End Dates, Auto-renew flag).
Frontend Integration (Where boosts appear):
Micro Boost: Add "Trending Stores" carousel to ExplorePage.tsx.
Pro Boost: Update search/sort logic in SearchPage.tsx to multiply searchScore by 1.15 for boosted stores.
Max Boost: Add "Hero Banner Carousel" to the root app/page.tsx (Home page).
Boost Auto-Renewal:
Integrate boost renewals into the same Cloud Function used for subscriptions.


Phase 5: UI/UX Polish & Edge Cases
////////////////////////////////

Dispute Handling for Self-Arranged: Ensure buyers can still dispute and get a refund for the product cost even if they arranged their own delivery.
Refund Logic: If a seller fails to ship a courier order, automatically refund the shipping fee to the buyer's wallet/card.
Admin Dashboard: Build a UI to manage Couriers (add/edit rates) and view the separated financial ledgers (Escrow vs. Platform Revenue).
